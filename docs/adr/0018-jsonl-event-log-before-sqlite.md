# ADR-0018 — Append-only JSONL event log before SQLite

**Status:** Accepted · 2026-09-12
**Amends:** [ADR-0005](0005-store-trait-sqlite-first.md)

## Context
ADR-0005 chose a `Store` trait with SQLite as the first implementation. Re-examining that against
the actual vertical slice: the slice writes an event log and reads it back once, sequentially, to
generate a report and score predictions. There are no queries, no concurrent writers, no
retention policy, and no audit records — because there are no mutations (ADR-0012).

"Persisted event JSON, inspectable by a reviewer" is a stated deliverable. A reviewer who does
not trust FleetForge should be able to check every claim in the report themselves. `jq` over a
text file does that. Opening a SQLite database does it less well.

There is also a build-time argument. `sqlx` with its macro layer is a meaningful compile-time cost
on an 8 GB M1 for a component whose entire job is `append` and `read all`.

## Decision
`ff-record` writes an append-only JSONL file: one JSON object per line, each carrying its
`Provenance`, its monotonic sequence number, and its event type. The `Store` trait from ADR-0005
still exists and JSONL is its first implementation; SQLite remains a swap rather than a rewrite.

## Consequences
- The deliverable is literally the storage format — no export step that could diverge from the
  source.
- `tail -f` during a live run; `jq` afterwards. Both are useful during the demonstration itself.
- Append-only is the natural shape of the file, so the audit property is structural rather than
  enforced.
- No indexed queries. Reports are generated by a single sequential pass, which is correct at this
  scale and will not be at a larger one.
- File size grows without bound. One demonstration run is megabytes. Rotation is a real gap the
  moment FleetForge runs continuously.
- Hash-chaining for tamper evidence is not implemented. Noted in `THREAT_MODEL.md` as a known gap.

## Evidence that would justify SQLite
1. A report needing indexed lookup — "every PDB blocker across all runs" — rather than one pass.
2. Continuous operation, where unbounded file growth becomes a real problem.
3. Concurrent writers, which arrives with the execution controller (ADR-0012).
4. Audit records needing hash-chained tamper evidence, which arrives with the first mutation.

Items 3 and 4 arrive together with execution. That is the natural moment to implement the SQLite
`Store`, and it is why the trait exists now rather than later.

## Alternatives rejected
- **SQLite immediately.** Correct eventually; today it costs compile time and reviewer
  accessibility for capabilities nothing uses.
- **Both from the start.** Two implementations to keep in sync before either is exercised.
